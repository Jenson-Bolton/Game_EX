## Executive summary

`v0.1.4` replaces the WorldCompiler placeholder with the first complete offline-to-runtime data contract. A dependency-free C++20 compiler validates a strict normalised terrain stage, binds both staged files by byte size and SHA-256, writes deterministic little-endian `.gexworld` bytes, and reopens the result through the public runtime-only `GameEX::WorldFormat` reader. The package preserves source and transformation provenance, EPSG:5514 double-precision origins, tile-local float heights, a separate validity mask, canonical section offsets, and CRC-32 integrity.

The final Visual Studio workspace build passed all 10/10 tests in 1.11 seconds, including both GUI window smoke tests. A separately configured WorldCompiler build passed 4/4 tests in 0.55 seconds. Strict Doxygen 1.13.2 completed without warnings. Two independent compilations of the fixture produced identical 1,151-byte files with SHA-256 `A30C97F6283FE8E80165B500785B8B8625715FE5A29481E2ABC9FA691F13E5F3` and embedded CRC-32 `0x9aae2360`.

This is deliberately a codec and boundary result, not a real-world-data result. The only committed inputs are a four-sample project-authored fixture whose metadata grants no external reuse rights. The compiler has no LAS/LAZ, GDAL/PROJ, Python, network, or TESSERA adapter, and neither game nor editor loads the package yet.

## Scope and aim

The version asks whether Game_EX can establish a safe, reproducible world-data hand-off before choosing source-specific geospatial and machine-learning tooling. Accepted outcomes were:

- keep runtime consumers dependent only on `GameEX::WorldFormat`, not compiler or acquisition implementation;
- define one strict, auditable stage for a single normalised EPSG:5514 terrain tile;
- preserve original-source assertions separately from staged files the portable compiler can verify itself;
- retain national-scale horizontal and vertical origins as doubles while storing small row-major height offsets as floats;
- preserve no-data explicitly rather than encoding it as a magic height or discarding it through interpolation;
- encode a canonical little-endian package without C++ structure dumps or host-dependent ordering;
- reject corrupt, ambiguous, over-limit, unsupported, or path-escaping input before returning data;
- expose useful `validate`, `compile`, and `inspect` commands with stable process exit categories;
- compile and test independently of Engine, Game, SDL, OpenGL, Vulkan, and heavyweight geospatial dependencies;
- provide complete Doxygen, a normative format record, usage documentation, and release evidence.

Real DMR ingestion, coordinate transformation, multiple layers or tiles, reconciliation, renderer integration, and editor visualisation were explicit exclusions. [ADR 0009](../../decisions/0009-portable-terrain-stage-and-package.md) records the accepted persistent-format decision.

## Design and implementation

The implementation separates three responsibilities. `GameEX::WorldFormat` owns the public `WorldPackage`, terrain/provenance models, error classification, and verified reader. `GameEX::WorldCompilerCore` owns the strict stage parser and compiler. The executable is a small offline command-line composition root. Encoding remains internal to the compiler-facing implementation, preventing runtime code from treating authoring as a supported dependency.

Staging manifest version 1 has exactly 50 required keys. Unknown, duplicate, missing, empty, malformed, over-limit, or incorrectly spelled values fail closed. It represents one layer/tile in EPSG:5514 and requires explicit source identity/licensing assertions, source coordinate and vertical semantics, normalised-stage semantics, transformation history, owner, and hashes. Referenced height/validity paths must resolve canonically beneath the manifest directory; both exact byte sizes and SHA-256 values are verified before parsing.

The terrain contract uses `index = row * columns + column`, columns in positive X, and rows in positive Y. `origin_x`, `origin_y`, `origin_z`, and both spacings are finite binary64 values. Each height is a finite binary32 offset, so valid absolute elevation is reconstructed as `origin_z + double(height[index])`. One canonical byte per sample holds validity independently of height.

WorldFormat 0.2 begins with an explicit 128-byte header, followed by contiguous row-major heights, validity bytes, and a fixed-order metadata block. Integers and IEEE-754 bit patterns are written little-endian. Header sizes, offsets, counts, flags, EPSG code, total size, and metadata termination are canonical rather than advisory. CRC-32/ISO-HDLC covers the entire file while treating its own four-byte field as zero. Reader limits are 4,096 samples per dimension, 4,194,304 total samples, 4,096 bytes per metadata string, and 64 MiB per package.

`compile` atomically reserves a destination with a sibling `.lock` directory,
refuses any destination or legacy sibling `.part` path it does not own, writes
and closes `package.part` inside the owned lock directory, and publishes with an
atomic no-replace hard link. It never opens or removes the legacy sibling and
then removes only its private partial file and lock directory. `inspect`
verifies the package through the public reader, derives numeric bounds and valid
height extrema, and reports all retained provenance. Exit codes distinguish
usage, invalid manifest, invalid staged input, invalid package, I/O, and
unexpected failures. The exact schema and bytes are defined by the [normative
format document](../../architecture/world-package-format.md); the [WorldCompiler
guide](../../../WorldCompiler/README.md) documents operation.

## Evidence and method

The final workspace verification used CMake 4.2.3, Visual Studio 2022/MSVC 19.44.35224, the Windows 10.0.26100 SDK, and warning-as-error project settings:

```powershell
cmake --preset vs2022
cmake --build --preset debug --parallel 4
ctest --preset debug --output-on-failure
cmake --build --preset docs
```

CTest passed 10/10 tests in 1.11 seconds: four Engine job/startup modes,
`world_format.header`, the runtime-only `world_format.runtime_fixture`,
`world_compiler.pipeline`, `world_compiler.cli`, and the game/editor GUI smoke
tests. Doxygen 1.13.2 completed under the project's warnings-as-errors
configuration.

The compiler was then configured without the root workspace:

```powershell
cmake -S WorldCompiler -B build/verify-worldcompiler-v014-final -A x64 -DBUILD_TESTING=ON
cmake --build build/verify-worldcompiler-v014-final --config Debug --parallel 4
ctest --test-dir build/verify-worldcompiler-v014-final -C Debug --output-on-failure
```

The MSVC `/W4 /WX` build succeeded and all 4/4 standalone tests passed in 0.55 seconds. The golden-package test executable links only `GameEX::WorldFormat`; this independently demonstrates that runtime reading does not need the compiler core, SDL, or application composition.

A newly acquired provider-traceable source is required for the real terrain proof.

The fresh-source investigation stopped at inventory. On 2026-09-05 the official CUZK feed identified DMR 5G sheet `BYSH62`, title `Bystřice pod Hostýnem 6-2`, EPSG:5514 category, update value `2026-01-19T13:21:14+02:00`, and a declared 2,290,265-byte `BYSH62.zip` archive. Its polygon spans latitude `49.3999` to `49.4199` and longitude `17.6886` to `17.7254`, which contains the recorded Loukov station reference at `49.4103634`, `17.7153493`. The archive was not downloaded for this release, so no archive checksum, content acceptance, or licence/redistribution conclusion is claimed. These observations select the next acquisition candidate; they do not make it a `v0.1.4` data input.

## Discussion and reflection

Separating the original-source assertion from compiler-verified staged files is important. A portable compiler that begins after normalisation cannot prove that an external URL still serves the same bytes, but it can preserve that claim and refuse a mutated stage. The later source adapter must strengthen this boundary by acquiring and hashing the original itself; the current representation does not pretend otherwise.

The strict 50-key manifest is verbose for four samples, but every field corresponds to an ambiguity that becomes expensive once layers are combined: provider identity, licence, axis order, vertical reference, no-data, epoch, transformation, ownership, or content identity. Rejecting unknown keys prevents a misspelling from becoming silently ignored provenance. Human-readable text is appropriate for this small contract fixture, although it will not be the high-throughput interface for national terrain.

CRC-32 and SHA-256 have intentionally different jobs. The package CRC detects structural corruption during runtime loading. Staged SHA-256 values bind transformation inputs for reproducibility. Neither establishes legal rights or source authenticity, which still require the provenance and acceptance workflow.

The legacy audit reinforces the validity-mask decision. The older coursework grid filled 22.18% of cells and erased which samples were originally empty. Keeping validity independent allows later policies to distinguish observed, missing, and eventually derived data instead of making interpolation indistinguishable from measurement.

## Limitations and risks

- Only one EPSG:5514 terrain layer/tile is supported; package 0.2 has no extension mechanism, vector/material data, multiple tiles, LOD, compression, spatial index, or streaming table.
- Text staging is bounded and auditable but inefficient for production-sized national grids.
- Original-source size/hash values are asserted rather than reverified because source acquisition is intentionally absent.
- CRC-32 is accidental-corruption detection, not authentication or adversarial tamper protection.
- Files are read completely into bounded memory; performance and large-world streaming have not been measured.
- Publication requires same-filesystem hard-link support. A crash can leave a stale `.lock` directory containing its private `package.part`; the compiler preserves unknown artifacts, so an operator must investigate and remove a confirmed-stale reservation before retrying.
- Only the supported Windows/MSVC toolchain was available for execution. Non-MSVC warning policies are configured but not exercised in this report.
- The synthetic fixture tests format mechanics, not geographic correctness, terrain quality, coordinate conversion, source licensing, or scale.
- The world editor and game do not load, visualise, stream, or otherwise use `.gexworld` yet.
- The repository split decision remains mandatory before supported GDAL/PROJ, Python, network acquisition, or TESSERA dependencies are added.

## Next version

The next application-facing slices should introduce the shared Render API boundary, then render the same diagnostic content through explicit OpenGL 4.6 Core and Vulkan 1.3 selections. The editor can then load one `.gexworld` through `GameEX::WorldFormat` and visualise terrain/validity separately before any source reconciliation.

At the first real-data slice, resolve the WorldCompiler repository split, acquire the fresh CUZK DMR 5G `BYSH62` candidate for the Loukov/Bystřice proof under a complete immutable provenance record, and add the minimum source adapter outside runtime. TESSERA 2024 remains an offline semantic input after terrain, with decoded probabilities/material weights rather than raw 128-dimensional embeddings in the renderer.
