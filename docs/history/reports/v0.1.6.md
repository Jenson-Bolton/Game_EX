## Executive summary

`v0.1.6` completes the first real cross-technology renderer milestone. A new
`GameEX::RenderVulkan` implementation requests Vulkan 1.3 and synchronization2,
builds a deterministic sRGB FIFO swapchain, clears it through transfer commands,
and presents the exact same linear `(0.035, 0.065, 0.110, 1.0)` diagnostic frame
used by OpenGL. Both game and world editor now accept explicit OpenGL, explicit
Vulkan, or Vulkan-first automatic selection without exposing native types in
shared code.

The implementation remains deliberately smaller than a conventional rendering
hardware interface. It adds no shader, SPIR-V, pipeline, mesh, buffer, image,
descriptor, camera, or world-data resource. Successful native presentations
through both APIs and identical semantic clear input are the evidence; this
report does not claim captured-pixel equality.

Vulkan ownership includes partial-start cleanup, deterministic device/queue and
surface policy, one frame in flight, synchronization2 layout transitions,
per-swapchain-image present-wait semaphores, zero-extent and surface-change
deferral, transactional replacement, and terminal native-frame errors. A
required-validation smoke performs at least 32 visible presents and fails on an
error-severity validation message.

The supported machine used LunarG SDK/headers/validation `1.4.357.0`, system
loader `1.4.321`, and an NVIDIA GeForce RTX 3060 Ti advertising device API
`1.4.329` with driver `595.95`. The final fresh workspace MSVC `/W4 /WX` build
and strict Doxygen verification are recorded below with the final CTest result.

## Aim and acceptance criteria

The question for this version was: can the existing neutral diagnostic frame be
presented through a robust Vulkan 1.3 implementation, while selection remains
explicit, observable, and safe around native window lifetime?

Accepted outcomes were:

- add a real Vulkan 1.3 backend without changing the diagnostic scene or
  inventing future resources;
- keep Vulkan and SDL types/dependencies private to `GameEX::RenderVulkan`;
- request and verify Vulkan 1.3 plus synchronization2;
- choose devices, queues, sRGB surface format, extent, image count, composite
  alpha, and FIFO presentation deterministically;
- support separate graphics/present queues and require transfer-destination
  swapchain format/usage;
- use one frame in flight, synchronization2 transitions, transfer clear,
  submit2, and presentation with valid binary-semaphore reuse;
- make swapchain replacement transactional and safely defer zero extents;
- distinguish retryable deferral from terminal uncertain native-frame failure;
- expose optional validation and a dedicated required-validation smoke;
- add exact `--renderer=opengl|vulkan|auto`, with omission as auto, explicit
  no-fallback, fresh attempts, and a narrow typed pre-visibility fallback gate;
- make timed GUI tests require presentation rather than process survival;
- support explicit SDK/env/conventional Windows discovery and a Vulkan-off build;
- retain standalone Engine/full workspace builds, strict warnings, Doxygen,
  documentation, and per-version history.

Explicit exclusions were shaders, geometry, terrain display, source adapters,
real data, screenshots, pixel equality, UI panels, gameplay, and simulation.

## Design and implementation

### Shared API and dependency boundary

`Renderer::render_frame` now returns `FramePresentationResult`: `presented`,
`deferred_zero_extent`, or `deferred_surface_change`. Neutral diagnostics add a
presentation description, successful presentation count, and debug error count.
The exact `DiagnosticFrame` contract remains finite linear float RGBA values in
`[0, 1]`.

`GameEX::RenderVulkan` publicly exposes only `VulkanValidationMode`, a small
ordinary C++ configuration, and a factory returning the neutral interface.
Vulkan headers/library, SDL3, and `sdl_window_access.hpp` are private build
dependencies. `GameEX::Core`, `GameEX::Render`, public game/editor code, and
`GameEX::WorldFormat` do not depend on native graphics types. A Vulkan-disabled
build removes the concrete target while leaving neutral/OpenGL targets usable.

### Instance, validation, device, and queues

Startup verifies the loader version before requesting API 1.3. SDL supplies the
required instance extension names. Required validation additionally checks
`VK_LAYER_KHRONOS_validation` and `VK_EXT_debug_utils`; optional mode enables
them only when both exist. The callback is non-throwing, counts error-severity
messages atomically, and reports diagnostics without a C++ stream exception.

Each physical device is evaluated for API 1.3, Vulkan 1.3 synchronization2,
swapchain extension, surface queues, FIFO, transfer-destination surface usage,
and a permitted sRGB format with transfer-destination format features. Suitable
devices rank discrete, integrated, virtual, CPU, then other, with UUID and stable
identity tie-breaks. Queue policy selects the lowest combined graphics/present
family or the lowest separate pair. The logical device enables synchronization2
and obtains one queue from each selected family.

Every Vulkan/SDL create operation writes to a null-initialized temporary and
commits the handle only after success. A failed create therefore cannot leave an
undefined output in persistent cleanup state. Failed startup enters a
shutdown-capable state so the application graph can release only known-valid
handles in reverse dependency order.

### Swapchain and frame path

Surface format is B8G8R8A8_SRGB then R8G8B8A8_SRGB, always with
SRGB_NONLINEAR. No arbitrary non-sRGB fallback exists. The Vulkan convention of
one undefined surface format resolves to B8 sRGB only when the colour space is
SRGB_NONLINEAR. FIFO is mandatory. Extent uses fixed capabilities or clamps SDL
drawable pixels; image count is minimum plus one where allowed; composite alpha
uses opaque, pre-multiplied, post-multiplied, then inherit.

A swapchain generation owns its handle, images, known-layout flags, and one
present-wait semaphore per image. The replacement generation is completed before
the active generation changes. A zero extent returns deferral. Out-of-date or
suboptimal results mark the generation dirty; runtime recreation errors are
`presentation_failed` rather than selection fallback signals.

After waiting for the sole frame fence, the renderer acquires an image, records
sync2 barriers from undefined/present to transfer destination and then to present,
and clears with `VkClearColorValue::float32`. `vkQueueSubmit2` waits on the
acquire semaphore and signals the semaphore owned by that image;
`vkQueuePresentKHR` waits on it. Reacquiring that image establishes safe reuse
independently of the submission fence. The float clear is interpreted as linear
for the selected sRGB destination, matching the OpenGL framebuffer-sRGB intent.

Input validation and deferral remain retryable. Any exception after native frame
work begins changes either backend to `failed` before propagating. This prevents
another call from reusing a possibly consumed semaphore, unsignalled fence,
partial command buffer, or uncertain OpenGL state. Shutdown accepts failed state.

### Visibility and selection

Application startup performs renderer start and one hidden presentation attempt
before showing its window. A hidden drawable may be zero, so the attempt can
defer; the loop must then obtain a real visible presentation. Monotonic
`reached_window_visibility()` evidence distinguishes a safe selection failure
from a visible runtime failure. A timed run with no presentation raises
`presentation_failed`.

The parser accepts one renderer option and one bounded unsigned quit timer in
either order. Explicit OpenGL/Vulkan makes one attempt. Auto tries Vulkan and
falls back only when the reported backend is Vulkan, the code is unavailable or
initialization_failed, and visibility was never reached. Before fallback it logs
the preferred category, stage, and message. Each attempt constructs a new SDL
Platform and Application. Post-visibility, presentation, shutdown, inconsistent
backend, non-renderer, and OpenGL fallback failures are propagated.

### Build and validation isolation

`GAMEEX_ENABLE_VULKAN` defaults on. Windows SDK discovery is:

1. explicit `GAMEEX_VULKAN_SDK_ROOT`;
2. `VULKAN_SDK` environment variable;
3. highest naturally sorted valid `C:/VulkanSDK/*` installation.

Explicit or environment roots fail immediately when the header/import library
pair is absent. CMake seeds the recognised FindVulkan variables before requiring
version 1.3. The discovered SDK in this run was `C:/VulkanSDK/1.4.357.0` with the
environment variable unset. Independent probes passed explicit-root precedence,
environment-root selection, conventional fallback, invalid-root failure, and
Vulkan-off configuration.

The validation test sets `VK_LAYER_PATH` to the selected SDK `Bin` and replaces
implicit discovery with an existing empty build directory. It unsets inherited
additive/forced layer controls and disables implicit layers. This was necessary
because stale Epic Overlay registry JSON otherwise reached the debug callback as
two loader errors before engine work. The controlled environment produced no
such messages and did not suppress errors from the requested Khronos layer.

No shader tools are required or treated as FindVulkan components. The existing
GLAD 2.0.8 content and LF normalisation controls remain unchanged:

## Test design

The Vulkan policy suite uses fixed inputs and shuffled enumeration order. It
covers combined/separate queues, device class/UUID/suitability, B8/R8 and
undefined surface formats, non-sRGB/empty rejection, fixed/clamped extent,
bounded/unlimited/inconsistent image counts, and composite-alpha preference and
rejection.

Renderer-selection tests cover parser defaults, explicit auto, both option
orders, malformed/empty/repeated/conflicting values, explicit one-attempt
behaviour, Vulkan-only auto success, both eligible fallback categories, preserved
preferred failure, failed fallback, and every forbidden fallback stage/category.
Fake Application tests prove monotonic visibility evidence, exact hidden
deferral/show/visible-present order, timed permanent-deferral failure, terminal
native-frame failure, and reverse cleanup.

The dedicated Vulkan smoke performs a hidden attempt and at least 32 successful
presentations after show. It checks API baseline, sRGB/FIFO diagnostics,
presentation count, and debug error count. The validation variant requires the
layer and repeats the batch. OpenGL smoke and both explicit game/editor backends
remain separate tests; auto has its own production composition smoke.

## Data, assets, and provenance

No terrain, imagery, vector, model, texture, shader, or machine-learning asset
was added. The only `.gexworld` fixture remains the project-authored synthetic
2x2 EPSG:5514 compiler fixture from v0.1.4. Neither application loads or displays
it. This release has no real source adapter and makes no geographic accuracy,
licensing, or layer-combination claim.

SDL3 and audited GLAD are retained dependencies. LunarG Vulkan SDK 1.4.357.0 is
an external developer-machine dependency and is not copied into the repository.
Runtime loader/driver components remain system/vendor responsibilities.

## Discussion and reflection

The transfer-clear route was the right-sized proof. It exercises instance,
surface, device, queues, feature negotiation, swapchain, command recording,
synchronization, colour format, repeated presentation, and cleanup without
allowing the Vulkan backend to dictate an untested resource abstraction. The
next shared API additions can now be justified by actual terrain-view needs.

Several issues only became visible under adversarial review. An arbitrary
surface-format fallback would have broken linear-colour semantics. A single
render-finished semaphore would have been unsafe because the submission fence
does not prove presentation has consumed its wait. Writing create outputs
directly into persistent handles could have made failure cleanup destroy
undefined values. Retrying after submission failure could hang on a reset but
unsignalled fence. The final design makes each invariant explicit instead of
depending on observed success on one driver.

The hidden-first-present rule also needed refinement. Some platforms legitimately
report zero drawable extent before show, so “successful present before
visibility” was too strong as a universal current contract. The implementation
retains the useful ordering—renderer initialisation and a hidden attempt before
show—while requiring a later real present for automated acceptance.

Hermetic validation demonstrated that host overlays are part of test design.
The initial run detected stale third-party manifest errors rather than an engine
VUID. Replacing implicit discovery with a controlled empty directory removed
that unrelated variability while still requiring the requested validation layer.

## Limitations and risks

- The scene is a clear colour only; no shader, geometry, depth, resource lifetime,
  coordinate precision, or terrain orientation is exercised.
- No screenshot or pixel comparison is made. Different APIs/drivers/displays may
  differ even when semantic linear clear input and sRGB intent match.
- Only Windows/MSVC/NVIDIA was executed. Another driver vendor and non-Windows
  SDK/runtime need independent evidence.
- Conventional device-idle swapchain replacement is used. Unextended
  KHR_swapchain lacks a fully signalled WSI presentation-retirement point for
  every old resource; maintenance1 presentation fences remain a follow-up.
- Device loss and surface loss are terminal; there is no recovery/restart policy.
- Vulkan validation is opt-in for ordinary applications and required only by its
  dedicated smoke.
- OpenGL still uses process-global GLAD procedure state and one-context ownership.
- Game/editor still do not read `.gexworld`; the current data is synthetic.

## Next version

`v0.1.7` should load the existing synthetic `.gexworld` package through the
runtime-only reader and visualise terrain height plus validity in the standalone
world editor under both OpenGL and Vulkan. Before coding, specify the smallest
shared vertex/index/resource, shader source/build/reflection, camera, and
render-world extraction contracts. The viewer should show the data before any
combination and retain explicit backend smokes.

Real DMR/TESSERA or other Czech data remains later work. Resolve the
WorldCompiler repository split before adding GDAL/PROJ/Python/network/ML
dependencies, and accept each source's licence, edition, checksum, CRS, and
redistribution record before ingestion.
