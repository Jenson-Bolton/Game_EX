## Executive summary

`v0.1.0` restarted Game_EX as a warning-clean C++20 workspace with explicit Engine, WorldCompiler, and Game boundaries. It produced two real SDL3 desktop composition paths—a game window and a world-editor window—plus a headless compiler placeholder and a logical runtime world-header contract. Three CTest checks passed, both GUI applications were observed running together and exiting cleanly, and strict Doxygen generation covered all 14 C++ source/header inputs without warnings. The principal limitation was intentional: this version established architecture and lifecycle only, not rendering, simulation, editor tooling, or a production data format.

## Scope and aim

The aim was to prove that the restarted repository could build and run the minimum application skeleton without carrying forward the old monolithic direction. Acceptance required:

- independently structured Engine, WorldCompiler, and Game CMake projects composed by one workspace;
- an SDL3-backed game window and a separate SDL3-backed world-editor window;
- a headless world-compiler entry point and a runtime-facing logical header contract;
- warning-clean builds, automated lifecycle/contract checks, and strict generated API documentation;
- durable project, architecture, section, development, and decision documentation.

The version explicitly excluded a renderer, simulation, editor workflow, real-world ingestion pipeline, stable binary world schema, ECS, jobs, audio, input mapping, and repository split.

## Design and implementation

The workspace composes three projects while preserving their dependency direction:

- `GameEX::Core` owns platform-neutral application and window contracts.
- `GameEX::PlatformSDL` privately implements those contracts with pinned SDL3.
- `game_ex` and `game_ex_world_editor` are separate composition roots; neither includes SDL headers.
- `GameEX::WorldFormat` exposes the small runtime contract used by Game.
- `game_ex_world_compiler` remains offline and headless rather than becoming a runtime dependency.

The logical world header establishes ownership and compatibility checks without serialising the in-memory C++ object representation. The renderer boundary was deliberately left open; SDL provides platform/window services only and is not treated as the Game_EX renderer.

These choices are recorded in [ADR 0001](../../decisions/0001-three-project-workspace.md), [ADR 0002](../../decisions/0002-sdl3-platform-boundary.md), and [ADR 0003](../../decisions/0003-initial-world-editor-placement.md).

## Evidence and method

The implementation was configured and built with the Visual Studio 2022 preset and strict target warnings. The retained reproducible command set is:

```powershell
cmake --preset vs2022
cmake --build --preset debug
ctest --preset debug
cmake --build --preset docs
```

Evidence recorded during implementation showed:

- all three registered CTest checks passed: the world-header unit check, game-window smoke check, and editor-window smoke check;
- each smoke path completed SDL initialisation, native window creation/showing, event pumping, and orderly teardown;
- the game and editor windows were also launched together, visually observed as separate open desktop windows, and exited with code zero;
- Doxygen completed with warnings treated as errors and included all 14 C++ headers/source files in scope;
- an independent code/documentation review was completed and its identified issues were corrected before the foundation commit.

The GUI checks establish lifecycle behaviour only; a blank window is not evidence of rendering capability.

## Data and assets

No geographic or simulation dataset was committed or processed in `v0.1.0`. SDL `3.4.14`, provided by the SDL project under the zlib licence, was the only fetched project dependency. It was acquired during the 2026-09-04 foundation build from the [official release archive](https://github.com/libsdl-org/SDL/releases/download/release-3.4.14/SDL3-3.4.14.tar.gz), whose expected SHA-256 is `30d4aa2b3037718142b32dffd4e72f917ebb6cc5227150e7bb9c45efb2153aeb`. CMake downloads the archive into the ignored build tree; SDL source, binaries, and generated documentation are not committed or redistributed in this repository.

## Discussion and reflection

The thin vertical slice proved the build graph and application lifecycle before those boundaries accumulated feature code. Keeping SDL private prevented the first visible result from defining the future rendering architecture. Separating the editor executable demonstrated shared engine composition without coupling the offline compiler to GUI services.

The version number, however, was repeated in independent project declarations and the evidence had no per-version report at publication time. That made release identity and history easier to drift. The next version addresses that workflow weakness without rewriting the original commit.

## Limitations and risks

- Both windows are blank. They prove platform composition, not graphics output or editor interaction.
- `WorldHeader` is a logical contract only. Treating its C++ memory layout as a file format would be incorrect and non-portable.
- The compiler reports a safe placeholder result but does not ingest, validate, transform, or package data.
- The smoke tests require a desktop environment and do not replace renderer or interaction tests.
- No real Czech Republic data, provenance manifest, coordinate transform, or layer-combination rule was exercised.
- The mature editor project boundary remains provisional until its document, UI, and compiler-orchestration responsibilities are known.

## Next version

`v0.1.1` establishes the working agreement, report/history system, and one centrally propagated project version. Subsequent patch versions should introduce separately verifiable compiler, real-data, and editor-viewer slices. `v0.2.0` should be the first roll-up report for an integrated world-data/compiler/editor capability, but only after its data, coordinate, renderer, and layer-combination specification gates are resolved.
